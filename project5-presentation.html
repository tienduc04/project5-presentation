Project 5 — Julia Production Optimizer
Module 5 checks the plan from Module 4 against due dates, order quantities and machine capacity, and projects inventory after the plan. Replan rules: on-time rate below 90%, any machine above 95% utilisation, a stockout, or orders missing / short. If yes, it writes adjustment_data.csv and sends it back to the Data module. If no, the plan is implemented and monitored. At planning time there is no actual production data yet; comparing with actual output would be the next step after implementation.

Project 5 — Julia Production Optimizer
Summary: 5 modules create a closed loop. After Module 5 the system asks: is an adjustment needed? YES (a KPI is missed) → adjust and go back to Module 1 (data module) and run the pipeline again. NO (all KPIs met) → the loop ends and the plan is released. Output: each order has a machine, quantity, start-finish time and score/reason.

Exit condition: on-time rate at least 90%, no machine above 95%, no stockout and no missing or short orders, so no adjustment is needed and no adjustment_data.csv is written. The loop ends here — the plan is frozen, released to production and monitored. A new cycle only starts when something changes: new orders, a machine breakdown or a demand shift.
